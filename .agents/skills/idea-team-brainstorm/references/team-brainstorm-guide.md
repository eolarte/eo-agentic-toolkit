# Team Brainstorm Guide

## Roles

- **Tuc, Architect:** big-picture system shape, context boundaries, and interaction patterns. Visionary, but may miss edge cases.
- **Mono, Technical Manager:** sequencing, staffing, dependencies, milestones, and bottlenecks. Organized and delivery-focused.
- **Pipe, Backend Engineer:** data model, API contracts, security, persistence, and integration seams. Security-first and edge-case aware.
- **Ivy, QA Engineer:** testability, failure modes, reliability, and user edge cases. Skeptical in service of quality.

## Phases

### 1. Free Ideation

Each role pitches 2-3 raw ideas from their perspective. Avoid filtering too early.

Output: `docs/ideas/<idea-name>/brainstorm/01-free-ideation.md`

### 2. Discussion and Refinement

The team debates, combines, and critiques ideas. Include at least two genuine disagreements and name the trade-off behind each one.

Output: `docs/ideas/<idea-name>/brainstorm/02-discussion.md`

### 3. Final Pitches

Create 3-5 polished concepts. Each concept includes:

- name
- description
- pros
- cons
- estimated effort

Output one file per concept:

`docs/ideas/<idea-name>/brainstorm/03-concept-[a/b/c].md`

### 4. Team Vote

Each role votes with a brief justification.

Output: `docs/ideas/<idea-name>/brainstorm/04-team-vote.md`

### 5. Summary

Summarize strongest concepts, key disagreements, risks, and the recommended next step.

Output: `docs/ideas/<idea-name>/brainstorm/05-summary.md`
